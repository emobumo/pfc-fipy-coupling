## 机器不稳定与检查点（2026-09-23）

**2026-09-23 上午**：这台机器在持续数值负载下随机损坏内存——24 小时内两次蓝屏、停止码
**互不相同**（0xFC、0x20001），一条 WHEA 已纠正硬件错误，以及 numpy `umath.pyd` 里的用户态
段错误（0xc0000005）。四个月无事，而这 24 小时正是项目第一次跑 1~2 小时满载算例：**变的是
负载，不是软件**（30 天内无 Windows 累积更新）。

**根因（2026-09-23 下午）**：CPU 微码原为 **0x123**，早于 Intel 针对 Raptor Lake 电压退化的
三次修复（0x125 / 0x129 / 0x12B）；BIOS 为 2024-06-06 的 N0CN24WW。用户已刷至
N0CN35WW（2026-04-17），微码 0x123 → 0x133，全部修复覆盖。

**刷 BIOS 没有解决问题（2026-09-23 夜，证伪"已修复"）**：修复后约 6 小时满载内又出现一次
`multiarray.pyd` 段错误（21:02）和**第三种停止码 0x101 CLOCK_WATCHDOG_TIMEOUT**（22:09，
微码仍为 0x133）。0x101 = 某核心停止响应时钟中断，是 Raptor Lake 退化最典型的症状。三种互不相同的
停止码 + 修复后复现 ⇒ **CPU 很可能已物理退化**，微码只能止损不能复原。**处置：报联想售后（笔记本
CPU 焊在主板上，通常换主板）。**查微码用
`HKLM\HARDWARE\DESCRIPTION\System\CentralProcessor\0` 的 `Update Revision`；该值与
`Previous Update Revision` 相同即表示 Windows 未在系统层覆盖，BIOS 是唯一途径。
**注意：电压退化累积且不可逆**，微码只阻止继续恶化，不能撤销已发生的损伤。

限频（`powercfg` 的 `PROCFREQMAX`/`PROCFREQMAX1` = 4200 MHz）**当前生效**。曾于刷 BIOS 后解除，
理由"缺陷已修复"被 0x101 证伪后于 09-24 重新加上——对已退化的核心，降频压低了稳定所需的电压，
是维修前的标准维稳手段。微弱的旁证：限频期间（约 3 小时）零故障，解除后约 6 小时两次故障。两条实测结论要保留：百分比档位
**`PROCTHROTTLEMAX` 在这台机器上完全无效**（设 90 与设 100 峰值都是 ~5.3 GHz，别用也别信它），
绝对频率上限才咬得住（~5.3 → ~4.0 GHz）。刷 BIOS 不会清除电源设置。

**刷 BIOS 会重置拯救者的散热/性能模式，代价是三倍**（固定负载 27 → 75~92 s）。它极易被误读成
"微码修复的性能代价"，从而得出应该回滚 BIOS 的荒谬结论。**区分方法是看采样序列的形状而不是峰值**：
微码若限制睿频，峰值先降；实测峰值几乎不变（242% → 238%，均 ~5.3 GHz），而持续能力两秒内从
5.2 GHz 掉到 2.2 GHz——这是**功耗墙（PL1）**的形状。用 Fn+Q 或 Legion Zone 切回性能/野兽模式后，
持续频率从 ~2.4 GHz 回到 ~4.8 GHz。**推论：在功耗被压的状态下测任何频率上限的影响都是在测噪声**
（限频 vs 不限频当时读数 86 vs 75~92 s，天花板根本没机会生效）。

固定负载基准（`ckpt_integration.py`，576 单元 62 步）的量级：良好状态下约 **27~31 s**；测量本身
带 ±20% 的轮间噪声（短负载 + 睿频驻留波动），**不要用它分辨 15% 以内的差异**。

由此定下两条工作规则（**与微码版本无关，长期保留**）：

1. **长算例必须能续跑**。`src/analysis/run_checkpoint.py` 保存跨步携带的状态并逐位恢复；
   五个工程算例全部接入，默认每 200 步存一次，崩溃后**重跑同一条命令**即可续上。
   跨步携带的量是：`pressure`、`saturation`、**`mobility_face`（滞后的 Picard 迁移率）**、
   **`last_div_q`（`compute_adaptive_dt` 读的上一步通量）**、`face_yield_latched`、
   两个 `*_initial_for_ledger` 基线、三个体积台账、`flow_step_index`、`dt_last`。
   分段算例另需 `STAGE_STATE_KEYS`（孔隙率、渗透率、四个迁移率别名、台账、
   **`interior_dirichlet_mask`/`value`**）——**漏掉源掩码不会报错，只会让续跑从整根孔注浆，
   得到一个能跑完但错误的结果**。存盘在两个槽位轮换 + 指针文件，写一半崩只丢一个间隔；
   配置指纹不符（几何/参数/子算例变了）时拒绝续跑而不是静默续错。
2. **静默损坏比崩溃更危险**。随机内存损坏不一定崩，可能只把某个浮点数改掉。算例是确定性的，
   所以**凡是要写进论文的锚点数字，跑两遍逐位比对**；两次独立运行 bit 级一致即基本排除静默损坏。
   崩溃是运气好的情况。

## 充填诊断（`src/analysis/fill_diagnostics.py`，纯后处理，不进求解器）

三层嵌套评价域，层间差集即诊断结论：`Ω_design`（设计加固体，外部给定）⊃ `Ω_reach`
（可达域）⊃ `Ω_fill`（实际充填）。可达域**不是圆**，是路径积分 `∫λ ds ≤ p₀ − ρgΔy`
的最短路问题：边权 = 沿直线段积分的 λ + `ρgΔy`，Dijkstra（Π_g<1）/ Bellman-Ford（Π_g≥1 出现负边）。
`λ_f` 与求解器同构（调和 k、算术 φ）。**默认 16 邻域模板**（`stencil=16`），见下方度量修正。未充填单元按连通分量分为：`unreachable`（不算缺陷）、
`front_shortfall`（可达但未到、连通外部）、`bypass_void`（可达、被充填区包围——真缺陷）；
充填但超出可达域的记为 `overshoot`。另有 Q(t) 衰减判据（定压下"起压曲线"的对偶）与
体积—距离一致性（招金"注入量只够 5 m 却窜到 37 m"论据的自动化）。
`tests/test_fill_diagnostics.py` 21 测试；`scripts/diagnose_fill.py` 跑工程算例并出图。

**度量修正（2026-09-24，`a90e197`）——此前所有二维可达域数字都偏小，下面两段旧实测据此作废。**
连续问题里浆体沿直线付 λ，均质点源的精确可达域是圆。旧实现只沿四个面邻居走，度量是
|Δx|+|Δy|，斜向多算 41%，返回的是菱形：**只有圆面积的 60%，且在任何网格尺寸下都是 60%**
（度量误差不随加密消失）。这个偏差被读成了求解器"越界"与"屈服边缘蠕动"长达数日。
- 现默认 **16 邻域**（轴向 + 对角 + 日字），最坏度量误差 2.7%；半径 R/1.0275 内的单元全部可达，
  两种网格尺寸均验证。格点路径不可能短于直线，所以新模板**只会低估**可达域，最多 2.7%。
- **长边不许穿墙**：日字边跨过端点之外的单元，若只按端点计价会跳过单层胶结墙（λ 约为原生
  430 倍）。边按其直线段计价，穿过的每个面按求解器的面 λ 计入该面两侧的段长。纯对角边擦过
  单元角点、不经过任何侧单元，按"绕角的两条轴向路线中较便宜者、每条取其较贵的面"计价：
  **两侧都堵才封死，只堵一侧可从另一侧绕过**。
- `stencil=4` 保留旧代码路径、逐位复现，用于对照与非均匀网格。
- 七个新测试守这条线（Manhattan 本性、[1, 1.0275] 直线界、两种网格下圆的内外界、斜轴比、
  单层墙不可穿、斜向墙封角、单侧开口角点可过）；原 21 个诊断测试一条未改全部通过——它们
  都是一维或轴向情形，新旧度量本就一致。
- **修正后求解器是"没填满"而不是"越界"**：v0.6 线源梯度场 16 邻域可达 232 单元 / 1450 m²，
  求解器充填 199；均质 177 / 1106 m² vs 145。面积在 2.5 m 与 1.25 m 间收敛（1450 vs 1448 m²），
  旧度量卡在约 77%（1119 / 1123 m²）。
- **v0.6 核心比值（无求解器依赖，两次运行逐位一致）**：线源梯度 up/down **1.175**（1.25 m：1.179），
  均质 **0.888**（0.897）；求解器 1.157 / 0.91。梯度翻转重力偏置在 4/8/16/32 邻域、两种网格下
  **全部成立**，只是幅度从被放大的 1.26 回到约 1.18。
- v0.6 下孔底源与线源的可达域几乎相同（229 vs 232 单元，up/down 同为 1.175），因为 L_max
  （18~35 m）远大于孔长 17 m，外轮廓由远场决定——**孔底对照作为"换一种源几何"的检验，在
  v0.6 下区分力很弱**，引用时要说明。

**2026-09-22 在线源算例上的实测**（旧参数集、**旧四连通度量，越界解读已作废**）：

## 结构场与工程算例（2026-09-22，`src/structure/porosity_fields.py`、`cases/inclined_hole_{channel,staged}.py`）

数值为**参数集 v0.6 / 60×60 m 域**下的复跑结果（2026-09-22 夜）；括注为旧参数集的对应值。

  其余是连通外部的锋面缺额）——封闭域里靠
  "注到停"永远看不到空区。现场结束于"注不进"或"配额用完"，跑浆即后者先到。结构算例统一给
  基准停滞体积 **166.15** m³/m（旧 46.14）作配额；设计目标域 = 基准的停滞足迹（155 单元）。

- **"通道孔隙率几乎不影响"这条旧结论在 v0.6 下不成立**：φ 0.30/0.45/0.60 扫描旧参数为
  649/555/582 s、94/90/92%（平且非单调），v0.6 为 2469/1736/1521 s、90/75/66%（两列都单调）。
  按"位置的影响是孔隙率的数倍"表述，不要写成"孔隙率不重要"。
- **Q(t) 判据在 v0.6 下区分力下降**：孔口跑浆的 Q 尾/峰 0.045 已低于 0.05 停滞线（旧参数 0.101），

  记录读的，不是对停滞阈值读的，所以这是自动判据的局限，不是诊断量的局限。

  孔位浇成胶结体，**其后每一段 src 全 buried、V=0.00**（旧参数只有 3 m 短增量空转）。均质地层

## 黏度时变的两端界定（2026-09-25，`scripts/viscosity_aging_{bracket,gradient}.py`）

**用户决定不建时变流变模块**（⑦ 与台阶 8 取消）。理由写进论文：现场连续泵入，域内浆龄
a(x,t) 呈空间分布，严格模型需龄期输运 + μ(a)、τ₀(a) 试验关系；唯一文献（Lv et al. 2021,
Geofluids 7126013）只测了 0~40 min 表观黏度（W/C 0.5：μ = 869.75·e^{0.0135t} mPa·s，t/min，
e 折时间 **T = 74 min**），**没有 τ₀(t)**（作者模拟里 τ₀ 固定 3 Pa；图 5 "shear strength" kPa
量纲可疑且无时间趋势）。不采用全局 μ(t) 直接修正，以免把新浆赋予老浆状态。

**但全局 μ(t) 可作界限**：q ∝ 1/μ_p，λ 只含 τ₀，所以空间均匀的 μ(t) = μ₀f(t) **严格等价于时间变换**
dτ = dt/f(t)；指数增稠时 τ = T(1−e^{−t/T}) < T，即"常黏度解截停在 τ = T"。浆龄 ≤ t，全局 μ(t)
是**慢端**（全部按最老浆），常黏度是**快端**（全部新浆），真实状态**预期**居间（二维非均匀龄期下
无逐点比较定理，写"预期"不写"严格"）。锋面浆最先注入、最老，慢端对锋面本身描述尚可。
分段每段新浆，时钟逐段重置。黏度时变**不改 L_max**（只含 τ₀），只截断趋近 L_max 的慢尾。

结果（40 个算例/段，`outputs/viscosity_aging/bracket.txt`）：
- **两端一致（稳健）**：全部通道算例（2~60 min 达同一终态）、随机场（29~43 min）、招金 A2/B2/C2
  跑浆（慢端 23/33/29 min 到 −63 m）、E2 封底、**分段第 1 段 48~139 min 停滞 < 初凝，后续段照样空转**。
- **只能给区间**：均质基准终态要 264 min（过初凝），95% 体积 114 min；**招金 D2 无通道慢端只到
  22%（96.8 → 20.6 m³/m），到不了 −56 m**。
- **核心比值（梯度场）**：慢端只注 91%，故单独复跑记录各时刻（`gradient_marks.txt`）。上/下比
  梯度 **1.13~1.21**（30/60/120/240 min、慢端 1.159/1.140/1.135/1.214/1.214，快端 1.157），均质
  **0.88~0.95**（快端 0.909）。**梯度翻转重力偏置在两端、各时刻全部成立**；幅度在 2.5 m 量化
  （±0.1）内。停滞行与锚点逐位一致（199 单元、264.32 m³/m）——这是 1.157 的第三遍独立运行。

## 块石绕流空区与致密包裹体（2026-09-26，`cases/boulder_bypass.py`）

现场施工人员称空区"可能形成于巨大骨架下"。**诊断新增 `enclosed_unreachable`（致密包裹体）**：
`classify_unfilled(..., solid_phi=1e-2)` 把 φ ≤ solid_phi 的单元（块石、围岩、前段胶结体）当固体——
不算空区、但与浆一样能把孔隙封住；被封住的未填孔隙按可达性拆为 `bypass_void`（可达）与
`enclosed_unreachable`（不可达，现场看是空区，成因是设计缺陷）。**不传 solid_phi 时逐位保持旧分类**，
所以既有锚点全部不受影响（4 个新测试守这条线，诊断测试共 32 个）。

**单块凸形块石做不出封闭空区**（路径积分下障碍物背后是向外敞开的缺口）。做得出的是**架空结构**：
盖石搭在两块支撑石上，下方留出**口朝下的凹形空间**。16×16 m、0.5 m 网格、源在上方 5 m、定压注到停滞：

| 变体 | 首次封闭时注入量（占可达孔隙） | 封闭区间 | 峰值 | 注到停滞后 |
|---|---|---|---|---|
| A 无周边环 | 33.6 m³/m（75%） | 75%~87% | 88% | 全部填满 |
| B 周边疏松环 φ 0.45（壁效应） | 23.9（49%） | 49%~65% | 88% | 全部填满 |
| C 环 + 块石下压密细粒 φ 0.03 | 23.4（49%） | 49%~≈100% | 75% 绕流 + 25% 致密 | 见下 |

- **周边环不是必要条件**：架空的凹形本身就能让两侧锋面在开口下方先合拢。环的作用是把封闭时刻提前
  到约一半注入量，**扩大了停注会留下空区的注入量区间**。A、B 型空区是**时间性**的，只有在填满前
  停注（跑浆超量、局部起压）才保留；这与"停注条件是黑箱"的现场描述自洽。
- **C 型实际上永久**：可达部分因细粒渗透率极低，几乎到注满才填上；不可达的 4 个单元（盖石下第一排，
  可达代价 1.13 p₀）**在其余区域全部停滞后数千秒才被填入**（t 964 → 3599 → 6580 s）——这是
  **正则化屈服在封闭区域里的伪蠕动**：真实 Bingham 浆静止后不再传压，正则化模型在屈服以下仍有微小
  流动性，封闭箱内压力慢慢涨向 p₀。**所以永久性包裹体以可达域判据为准，不以求解器长时间状态为准**；
  这也是"求解器只会没填满、不会越界"的**例外**：封闭高 λ 口袋 + 长时间，会出现越界。
- **困气（盖石下的气囊）模型做不出**：未充填单元取大气压 = 空气总能排出。写入局限；自下而上注浆 /
  排气孔是对应措施。

## 4.6 分段有效性试算（2026-09-26，`scripts/stage_ratio_pilot.py`，`outputs/stage_ratio/`）

停注按简介 3.2 的工序定义：**每段注至恒压注不进**（`run_sequence(budget=None)`），段间凝固后再钻进。
均质 φ = 0.10 / 0.14 / 0.18 × 一次注完 / 5→17 / 7→17 / 7→10→17，2.5 m，12 个算例。

- **"Δ/L_max = 1 为分界"被推翻**：Δ/L_max = 0.66 的段注进 43.9 m³/m，0.74 的段注入 0。
- **真正的判据：Δ > x_f**。x_f = 上一**有效**段（实际注进浆的段）停注时沿孔轴越过其孔底的实际
  胶结距离（`--extent` 输出 `extent.txt`）；Δ 从该段孔底起算（7→10→17 在 φ 0.10 时 10 m 段空转，
  17 m 段看到的 Δ = 10）。**12/12 与"是否注进浆"一致**。x_f/L_max = **0.34~0.80**：注至不进时锋面
  仍未到 L_max（Gustafson–Stille 渐近尾巴），源段越短沿轴扩得越少。所以设计准则应以停注时的实际
  扩散距离、而非理论 L_max 表述；它依赖停注判据（与黏度时变的慢端同向，都使 x_f 更短）。
- **按"注至不进"，分段的累计覆盖率从不优于一次整孔注浆**（可达区覆盖：φ 0.10 单段 70.7% vs 分段
  50.7~68.0%；0.14 71.8% vs 43.5~50.0%；0.18 82.9% vs 51.9~52.4%）。后续段有效时代价可以很小
  （φ 0.10 7→17 仅 −2.7 点），无效时 −20~−31 点；但有效不保证代价小（φ 0.18 5→17 第二段注进
  43.9 m³/m，覆盖仍只有 52.4%：第一段的胶结体挡住了回头的路）。代价的实体是**段间阴影区**
  （单段 22~35 单元 → 分段 24~90）。
- **论证含义**：分段的理由在成孔（松散体中钻不下去，须先注浆胶结再扫孔），不在注浆效率；4.6 的
  任务是给出"分段不空转"的条件（Δ > x_f）并量化分段的代价（阴影区）。
- 局限：只做了均质场；2.5 m 网格下 5 / 7 m 源段只有 2 / 3 个单元，x_f 带一个网格的量化误差，
  φ 0.14 7→17（Δ 10 vs x_f 10.1）是临界点。

## Picard 扫描与 ③ 的结论（2026-09-23/24，`scripts/picard_scan.py`）

③ 原定为"屈服边缘 Picard 不收敛导致越界蠕动，需 Anderson 加速或主动集求解器"。第 0 步扫描
（v0.6 线源、2.5 m）的结果把这个前提逐条拆掉了：

| 扫描 | 设置 | 越界（旧度量） | 结论 |
|---|---|---|---|
| E1 迭代预算 | 12 → 40 轮 | 25 → 25 单元，步数 2178/2179，t 差 2 s | **完全无效**，代价 ×3.4 |
| E2 正则化锐度 | m 40 → 120 → 400 | 25 → 17 → 17 | 解释约三分之一后饱和，非 1/m |
| E4 均质对照 | 均质 m=40 | 17 单元 / 11.7% | 与梯度相当，**与非均质无关** |

三条假设都不是主因，最后查出"越界"本身是可达域的度量偏差（上一节）。**③ 作为精度问题不成立**：
- 求解器相对真实可达域是略微**没填满**（约 14~19% 单元），不是越界；
- Picard 确实不收敛——末轮残差/首轮 **均值 0.60~0.67、p90 > 1**（极限环，不是慢收敛）——但
  12 轮与 40 轮答案逐项相同，所以它**只影响效率，不影响结果**。答辩被问"收敛判据可靠吗"时，
  这组对照就是回答。
- 因此 Anderson 加速 / 主动集**不再作为精度修复推进**。若日后要做，理由只能是效率。
- 求解器"没填满"的来源未单独拆分，候选有二：定压注浆锋面只能渐近逼近停滞位置（台阶 2b 的
  Gustafson–Stille 性质，t→∞ 才到），以及停滞判据（`STALL_PATIENCE`）在锋面仍在缓慢推进时提前判停。

## 分辨率与求解器实测（2026-09-22，`scripts/resolution_experiment.py`）

**⚠ 本节的核心解读已被 2026-09-24 的度量修正推翻，保留原文作记录。** 表中"越界"是相对**四连通**
可达域测的，而四连通可达域在任何网格上都只有真实值的约 60~77%。1.25 m 的 27~35% "越界"与
圆/菱形面积差 (π−2)/π = 36% 吻合——那是度量亏损在细网格上完整显现，**不是蠕动随步数累积**；
2.5 m 越界少，是单元太少把亏损量化掉了，不是"步数少所以准"。正确的结论是：**当前求解器下
分辨率可以放心调**，前提是用修正后的可达域做诊断。下面"Picard 触顶"的观察本身为真，但
Picard 扫描（下节）证明它不改变结果。

原文：**细化网格不换来精度，蠕动随步数累积。** 同一线源算例 2.5 → 1.25 m（144 → 576 单元）：

| | 2.5 m | 1.25 m |
|---|---|---|
| 均质 越界（充填超出解析可达域） | 1 单元 / 2% | **48 单元 / 27%**（同一时刻 t≈1532 s 也有 18%） |
| 梯度 越界 | 9 单元 / 18% | **61 单元 / 35%** |
| 梯度 up/down | 1.26 | **1.23**（解析可达域 1.28）——核心结论稳健 |
| 判停滞时间 | 1535 / 2100 s | 4243 / 5763 s，尾段 81~85% 步 Picard 触顶 |
| 机器时间 | ~1~4 min | 14~17 min |

原因：Picard 触顶的每一步都向外蠕一点，dx 减半 → dt 减半 → 同一物理时间两倍步数；小单元又更易触发"新单元过 0.5"，平台判据更难拦住。**2.5 m 的结果更接近解析可达域，是因为它步数少，不是因为它更准。当前求解器下分辨率不是可自由调的旋钮；唯一真正的出路仍是屈服边缘的 Picard 收敛。** 越界面积占比现在是量化这一问题的独立标尺。

**线性求解器**：FiPy 默认 PySparse PCG。576 单元长时程运行 **5 次崩 3 次**（段错误 / Fatal Python
error，非确定性，原生库问题）。**2026-09-22/23 补充：scipy 后端也会崩，且很可能不是 FiPy 的问题**——
真实堆算例于 step ~1225 段错误退出（exit 139），梯度算例在**独自运行**时同样段错误退出。同期
机器发生两次蓝屏，停止码**互不相同**（0xFC ATTEMPTED_EXECUTE_OF_NOEXECUTE_MEMORY、0x20001
HYPERVISOR_ERROR），另有一条 WHEA 已纠正硬件错误。不同停止码 + 用户态随机段错误 + 均发生在持续
数值负载下 = 典型的**硬件/固件不稳定**特征，而非某个原生库的缺陷。**（曾把 scipy 段错误归因于
并发，已证伪：梯度算例独自运行照样崩。）**所以"换 scipy 就不崩"是错的，但"并发导致崩"同样是错的；
可执行的表述是**崩溃可重试**：marching 是确定性的，重跑完成即等价。长时程算例建议做检查点。**已于 2026-09-22 经用户批准切换为 scipy 后端**（`run_local.ps1`
默认设 `FIPY_SOLVERS=scipy`，可用环境变量覆盖回 `pysparse` 复现旧值），并在 `equations.py` 中
按 `params["linear_solver"]`（默认 `"pcg"`）显式选求解器类：scipy 后端自带的默认是 LU 直接法，
它在验证阶梯上慢 **4.5 倍**（成千上万次一维小矩阵的逐次分解开销），scipy PCG 只慢 1.3 倍
（全套 677 s vs PySparse 514 s）。二维 576 单元长时程反过来：PCG 1532 s、LU 1009 s、PySparse 861 s，
大二维算例可按算例设 `linear_solver="lu"`。
