# 新终态（30 m 采场）重跑·第二阶段：求解器算例

2026-10-21。依据：主线“新终态重跑·第二阶段”。第一阶段见 `docs/xz_30m_stage1.md`。**求解器算例均仅计算一次**；本文数字取自后处理脚本，后处理连跑两遍逐字节相同。

## 〇、设置与运行

**主线对第一阶段的决定（照办）**：
- 3 条巷道、6 孔；
- 底层仍取 s ≤ 3 m，孔口管加长段仍到 s = 3.5 m；
- 情景二不另算；
- 用第一阶段已存的四套 0.5 m 网格，不改。
- 启动时脚本逐项核对过：基准算例的网格与 `grid_K1.25_s1.npz` 相同，K 组各算例的源单元与所存网格中的同一孔相同。

**统一设置**：
- v0.6 参数，含重力；
- 单线程（MKL / OMP = 1），次正规数置零，均从第 1 步起，中途未改；
- dt_cap 5 s；
- 终止规则：式（4-29）（ε 0.1、β 0.1、n_ref 0.20），或可达域外已充填达到可达域的 10%，先到者为准；
- 快照：可达域充填比例首次达到 0.90 / 0.95 / 0.99 时，存 S 场；
- 指标口径同第二步 B，只计可达域内；
- 单算例墙钟上限 10 h。

**运行**：

| 项 | 内容 |
|---|---|
| 启动 | 2026-10-20 23:25，A、B 组 10 个算例各占一个进程 |
| C 组 | 2026-10-21 08:59 才启动，见下文“运行中的一处问题” |
| 结束 | 15:09 全部结束 |
| 汇总脚本 | `scripts/xz_solver/stage2_summary.py`，输出 `outputs/xz_solver_30m/stage2.txt` |
| 两遍比对 | `stage2.txt` MD5 2595891d…；基准五个算例的 `cases.txt` MD5 8edc906d… |

**C 组的前提**：替换准备时已确认，出流边界不改 `src/` 即可实现；500 步检验的完整账目闭合到 1.2×10⁻⁹，主线口径的 3.8×10⁻⁴ 是浆液压缩储存，出流前就已存在。两项条件都满足，所以 C 组照做。

**C 组的做法**：
- 0.5 m 网格上的底层下端（7 个单元）每步结束时把 S 置回 0，这些单元就成为压力为 0 的出流单元。
- 出流量按求解器同一通量场累计。
- 运行到 V_in 达到对应封闭算例 0.95 快照 V_in 的 2 倍为止。式（4-29）与可达域外蠕变两条判据只记录、不终止。

**运行中的一处问题**：
- 原计划把出流算例与其封闭参照排在同一批（S1→O1、S4→O2）。
- `launch_batches.ps1` 把“S1,O1”中的逗号当成了 PowerShell 的数组分隔符，`run_cases.py` 只收到 S1，所以 S1、S4 结束后进程退出，O1、O2 没有接着跑。
- 已在该脚本中给参数加引号，并用“S1,ZZ”验证两项都能传到；O1、O2 于 08:59 单独启动。
- 其余 10 个算例都是单独一批，不受影响。

**K2、K3 按墙钟上限终止**：两者在 10 h 时停止。0.95 快照都已取到，K2 还取到了 0.99。
